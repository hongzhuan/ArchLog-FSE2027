# Release Note

## Important Changes

### RADOS Block Device (RBD)
- Add `RBD_LOCK_MODE_EXCLUSIVE_TRANSIENT` lock policy; this policy can hold the exclusive lock during operations and refuse to release it when a forced release request is encountered. [commit](https://github.com/ceph/ceph/commit/81eaf2e6bf3f55b8e21aac3e7a6ad42e935c0e91) [commit](https://github.com/ceph/ceph/commit/b67e960141d141285a818a23b2d585435fb00dea)

### RADOS Gateway (RGW)
- RGW triggers shard expansion early for versioned buckets; versioning status (including suspended state) is considered, and the per-shard object threshold is kept at least 1 to accommodate test configurations. [commit](https://github.com/ceph/ceph/commit/72092a63aa378af4b700ed8d24fdb32e232c2cb8) [commit](https://github.com/ceph/ceph/commit/b8a12ca1ebcddcee46b87a6dfea4e18e57b0cd43) [commit](https://github.com/ceph/ceph/commit/eb28b986907475bbc7a76908a6e155c116d06762)
- When rebuilding buckets and updating bucket metadata, bucket attributes are now overwritten rather than merged with old attributes, avoiding old attributes being incorrectly carried into the rebuilt bucket. [commit](https://github.com/ceph/ceph/commit/c5887a763b41aad5d89955e88337288f1019cccc)
- RGW uses the user's token when validating non-expired tokens with Keystone; only in flows that allow expired tokens does it continue using the admin token, thus supporting Keystone configurations without an admin token. [commit](https://github.com/ceph/ceph/commit/f9d209427d7d6f8c8928699190ad1adb1a279e31)
- Add `disable_multisite_sync_traffic` to RGW service spec, allowing the RGW multisite sync thread to be disabled or re-enabled when deploying the service. [commit](https://github.com/ceph/ceph/commit/59b3f2801118e1beda7ab07a29acd6f817d496d7)

### CephFS (Ceph File System)
- CephFS subvolume pool namespace now includes the group name; the pool namespace format for volumes using groups therefore changes, and documentation explains the new naming format. [commit](https://github.com/ceph/ceph/commit/d25695a5a6b5a360d308de207d402bdf109fade0) [commit](https://github.com/ceph/ceph/commit/93bb4d6806184bb54972ee16278833c1259bc539) [commit](https://github.com/ceph/ceph/commit/960f8f6e481dcab24dc2128504ee3eb4e709e139) [commit](https://github.com/ceph/ceph/commit/0b287c615cc4e834529afb48905dec46631d31e4)
- When the cluster is unhealthy, modifying filesystem `max_mds` requires explicit confirmation parameter `--yes-i-really-mean-it`; documentation and tests are updated accordingly. [commit](https://github.com/ceph/ceph/commit/fe45c051dc7ff829d874ff0f0c1832122cff5e40) [commit](https://github.com/ceph/ceph/commit/a1d9ba89a68de809399c1ba4221055c0f722064f) [commit](https://github.com/ceph/ceph/commit/90632e50b976b0d371b85819f9e9341fc63be83e)

### Cluster Management (Monitors and Managers)
- cephadm adds support for NFS service discovery configuration, allowing Prometheus to scrape NFS metrics via the service discovery endpoint. [commit](https://github.com/ceph/ceph/commit/2f9453b0b5d7b38b39287c5f31302bc082c0b10a)
- cephadm enables `--continue-on-error` when applying multiple service specs, and supports the continue execution option of `orch apply`, so that subsequent specs can still be processed if one fails. [commit](https://github.com/ceph/ceph/commit/3cadc37500600366a78c21ca5676bd61aeaca1e8)
- cephadm orchestrator returns `EINVAL` and parsing error information when parsing invalid YAML with trailing tabs, avoiding exceptions escaping command handling. [commit](https://github.com/ceph/ceph/commit/d9f78e86875cb992bcac93d6569d346f0d59f377)
- Monitor adds directed connection graph detection based on network topology, identifying network split scenarios and issuing netsplit health alerts. [commit](https://github.com/ceph/ceph/commit/a7477bef6484134887c19371ca3968090794fcc5)
