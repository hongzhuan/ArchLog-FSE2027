# Release Note

## Important Changes

### Core Compression Engine

- Add memory barriers in the fast match search test to force test operations to execute in the expected order. [commit](https://github.com/facebook/zstd/commit/197c258a79a94b60ec45020defc5fb6a2f570e80)
- The Zstd compressor adds a pre-splitter that divides input by block content before formal compression, to improve subsequent compression processing. [commit](https://github.com/facebook/zstd/commit/a5bce4ae84daa5885e61753fa98903964c3348bd)
- Add a faster block splitting heuristic for the fast compression strategy, so that the pre-splitting phase can match the processing characteristics of the dfast strategy. [commit](https://github.com/facebook/zstd/commit/da2c0dffd8c3e6306fcf2e8e5bd5f8ef97d7a999)
- Organize the pre-splitting level as a separate internal compression parameter, distinguished from the post-sequence block splitting switch. [commit](https://github.com/facebook/zstd/commit/01474bf73b357fe0c7bcf51f5cd41928462e2488)
- Fix the boolean type of the dictionary search switch, and explicitly cast the dictionary pointer difference to `size_t`, eliminating type mismatches on relevant platforms. [commit](https://github.com/facebook/zstd/commit/5359d16d8d646b2010b9d5ac07fbf747d432fdfe)
- Add the `compressSequences()` benchmark scenario in `fullbench` to measure the throughput of the external sequence compression API. [commit](https://github.com/facebook/zstd/commit/8ab04097ed9736923405e4928f928e49654e2c9a)
- Add a dedicated error code for the special case where external sequence compression cannot generate uncompressed blocks, for callers to identify this failure reason. [commit](https://github.com/facebook/zstd/commit/b339efff2bc9d11ce091bca62328c1884a38b5f3)
- When `validateSequences` is enabled, the external sequence and literal compression interfaces now return an error, avoiding unsupported behavior from combining this API with the sequence validation mode. [commit](https://github.com/facebook/zstd/commit/76445bb379fe74b0a8cddcce2658c111a2e8d7b0)

### Parallel Compression Module

- Optimize the `--patch-from` multithreaded path to directly reuse the current dictionary processing state, skipping the overhead of creating a temporary CDict. [commit](https://github.com/facebook/zstd/commit/7406d2b6eb91851db6a1cef10121de2a4c5a794a)

### Cross-cutting / Other Architecture-related Changes

- Add a dedicated pkg-config file for the multithreaded static library, and adjust static library installation rules and documentation to distinguish thread configurations. [commit](https://github.com/facebook/zstd/commit/f1f1ae369a4cefd3474b3528e8d1847b18750605)
- Improve attribute and builtin function adaptation for the IAR compiler, adding compatible implementations for bit operations, byte order, and entropy decoding. [commit](https://github.com/facebook/zstd/commit/2955d92ac02eb60b6d0d00e7c6cd3f013ac020e6)
- The old v0.6 decoder checks the workspace allocation result, returning an error on allocation failure instead of continuing with a null pointer. [commit](https://github.com/facebook/zstd/commit/1872688e0adb630e8710cb3d17846ca49f596e46)
- When dibio reads data exceeding 128 KiB, output a newline to keep the terminal output format correct after large block reads. [commit](https://github.com/facebook/zstd/commit/4c6a519fdd8caef500244b838beab7f7a160f70f)
- Enable weak symbol support for the RISC-V platform, allowing zstd_trace to select optional trace symbols based on platform capabilities. [commit](https://github.com/facebook/zstd/commit/6dbd49bcd04c42b0b4893d824b856563ae901b33)
- Note in the `ZSTD_compressSequencesAndLiterals()` documentation that this interface is incompatible with frame checksums, and clarify the notation for literals length constraints. [commit](https://github.com/facebook/zstd/commit/e0f3aaee467bbcb7e1653756eb426a9b7adde5d8)
- Expand external sequence compression tests to verify that the content size in the generated frame header matches `srcSize`, and that the window size does not exceed the input content length. [commit](https://github.com/facebook/zstd/commit/6f8e6f3c97c8e95527a29c4667edca6b793f798f)
- Write `MEM_writeLE24()` bytes of empty block header with 3, and change the target buffer lower bound to the actual required 3 bytes. [commit](https://github.com/facebook/zstd/commit/46e17b805b1bb2982583208da3b9184e377c2dd5)
- Change the MSVC 64-bit architecture check to check `_M_X64`, fixing the platform branch error in the bitstream implementation caused by misuse of `_M_X86`. [commit](https://github.com/facebook/zstd/commit/4bbf4a285d92e4cb5b37e0fd1d4af96c12c2c249)
- Add a Visual Studio Preview pre-release build script, and have the common build script locate the preview toolchain via `vswhere`. [commit](https://github.com/facebook/zstd/commit/a0872a837294ae9b18967e9e80342587f3089fb0)
- Fix the step configuration of the Clang PGO short test workflow so that tests under this compiler configuration can run normally. [commit](https://github.com/facebook/zstd/commit/897cec38760d1bb41e690225ba07b91c568e7cc8)
- In the zstd manual, state that `--max` uses maximum compression parameters, and note that this mode is very slow and resource-intensive. [commit](https://github.com/facebook/zstd/commit/8ae1330708b42c7f5751e94e02970e7ccb5d9731)

### Seekable Format Module

- Add build detection and fallback handling for libc environments lacking `fseeko()`/`ftello()`, so that the CLI and seekable decompressor can use available file positioning interfaces. [commit](https://github.com/facebook/zstd/commit/54c3d998a04a4002697a3a44293074cb01df54a5)
