# Release Note

## Important Changes

### Provider Subsystem

- Add SM4 assembly optimization for x86-64 CPUs with Intel SM4 instruction extensions, covering CBC, GCM, XTS, and CCM modes and integrating into build dispatch. [commit](https://github.com/openssl/openssl/commit/b12cd40e8bdf74b8eacaf2dc638e43986ae13b8d)
- Add an interleaved AES-CBC-HMAC-SHA1 assembly implementation for AArch64, and make the enc command recognize this combination as an unsupported ENC-then-MAC cipher. [commit](https://github.com/openssl/openssl/commit/86408fa8de640ebf09b08cb5fce8173d2dbc5702)
- Add an AES-CBC-HMAC-SHA512 assembly implementation for AArch64, and integrate it into the AES build and algorithm object definitions. [commit](https://github.com/openssl/openssl/commit/24f32f14e963fd2d73816e3c5c0bdef1a68be47a)
- Implement message update callbacks for signing and verification in the ML-DSA provider, allowing messages to be input in segments and completing pure message signing in the final phase. [commit](https://github.com/openssl/openssl/commit/341f1b7f70567aab668452c824d978768ea765b4)
- Provide a security-category property for the DH keymgmt implementation, reporting the security category of DH keys. [commit](https://github.com/openssl/openssl/commit/4577a4a59f5ec368f3bb062ed34abdf08dbbbd27)
- Provide a security-category property for the DSA keymgmt implementation, reporting the security category of DSA keys. [commit](https://github.com/openssl/openssl/commit/38517717920ac265a5cf94b496070b6387c980e5)
- Provide a security-category property for the EC keymgmt implementation, reporting the security category of elliptic curve keys. [commit](https://github.com/openssl/openssl/commit/5dcf3806e2503d40b7efc450ef8dbcf3b27373dd)
- Provide a security-category property for ECX keymgmt implementations such as X25519, X448, Ed25519, and Ed448. [commit](https://github.com/openssl/openssl/commit/077ed48edf66ffb5cbb29d3a0e6773f55d73a82c)
- Add a security-category property for the hybrid ECX/ML-KEM keymgmt implementation, reporting the security category based on hybrid key parameters. [commit](https://github.com/openssl/openssl/commit/2f1890eb181d3c13219d8c0991cbd6209338cf63)
- Add a security-category parameter for ML-DSA key structures and provider keymgmt implementations. [commit](https://github.com/openssl/openssl/commit/64328438f6c8ac4440167d89cbdacd8f8e02d7d0)
- Add a security-category parameter for ML-KEM key structures and provider keymgmt, and adjust corresponding level metadata. [commit](https://github.com/openssl/openssl/commit/32bc8e3434be2611a8d9f7959805a370377502ff)
- Add a security-category parameter for the RSA keymgmt implementation, allowing callers to query the security category of RSA keys. [commit](https://github.com/openssl/openssl/commit/4da326af2a7c71fbc791614e36c8acd42c47521d)
- Add a security-category property for SLH-DSA key structures and provider keymgmt implementations. [commit](https://github.com/openssl/openssl/commit/3b9f957c790b1dc1261f61bdb419f9b792fd9b04)
- Make the generic cipher implementation use a generator to automatically produce queryable and settable parameter tables, reducing manually maintained parameter name and type lists. [commit](https://github.com/openssl/openssl/commit/04e969d1f67b441c9f9474918c60085d20090ae8)
- Make the ChaCha20-Poly1305 cipher use a parameter name/type generator to generate context parameter tables. [commit](https://github.com/openssl/openssl/commit/83fa1b8b94d97371809cf23fb9a384a22581f3e4)
- Adjust cipher provider public headers and AEAD dispatch macros to use generated parameter lists and type information for GCM/CCM. [commit](https://github.com/openssl/openssl/commit/fa92dd9427665428d5132a395b71833bdf779b13)
- Refactor generic cipher parameter handling to uniformly process key length, IV length, and AEAD parameters through generated lists. [commit](https://github.com/openssl/openssl/commit/b0dcb391d2d966a541f4b563deea1abe54f7b89a)
- Add CRYPTO_THREAD_get_local_ex() and CRYPTO_THREAD_set_local_ex() to store data by thread-local key and OSSL_LIB_CTX combination, and clean up context-associated values on exit. [commit](https://github.com/openssl/openssl/commit/c1c2a333d34871f6210f2b5fb21ee631c4fb319e)
- Register dedicated OIDs for HKDF-SHA256, HKDF-SHA384, and HKDF-SHA512, allowing callers to load the corresponding HKDF algorithm by fixed digest name or object identifier. [commit](https://github.com/openssl/openssl/commit/d1a8d5a8330a8c9d939e18a22f7382af090cf108)
- Add LMS/LM-OTS parameter tables, key structures, and build entries, establishing base code for subsequent parsing of LMS public keys and implementing signature verification. [commit](https://github.com/openssl/openssl/commit/2a6a2adc8d9ec7476613f035f91877e5a65ab6f5)
- Implement LMS public key encoding length calculation and XDR data parsing, and update public key decoding interfaces and LMS EVP_PKEY documentation. [commit](https://github.com/openssl/openssl/commit/c64558ede85ed296753b42f74478b99bd89e7c34)

- Include LMS-related implementations in the FIPS provider build, and integrate LMS key management and signature verification into the FIPS algorithm registration path. [commit](https://github.com/openssl/openssl/commit/48af66aef72d482d41beafaf919b71e1dcb491b8)

- Add an Intel AVX-512/VAES accelerated AES-CFB128 implementation, and integrate it into AES assembly build and capability detection to improve throughput of this mode. [commit](https://github.com/openssl/openssl/commit/055dd1d8bb24ba307981091524fdf06da3771641)

- Add helper interfaces for provider cipher, digest, and MAC parameter loading that directly receive located parameters, avoiding multiple scans of the same OSSL_PARAM array. [commit](https://github.com/openssl/openssl/commit/688d0bc590514a164b19f5569ba09695925ddf62)
