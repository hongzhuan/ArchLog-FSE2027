# Release Note

## Important Changes

### Core Compression Engine

- Add an upper bound assertion after Huffman table log calculation to ensure the literal Huffman table log does not exceed the LitHufLog capacity limit. [commit](https://github.com/facebook/zstd/commit/b9566fc558830de2a3fd486961b674774c17b74e)
- Add the `ZSTD_c_prefetchCDictTables` compression parameter, allowing callers to control whether to prefetch the CDict match table. [commit](https://github.com/facebook/zstd/commit/2a128110d05aa5f67c9faee55a4fc538c169c16b)
- Supplement the public header file with descriptions of `ZSTD_c_prefetchCDictTables`'s purpose, default value, and applicable scenarios, explaining its control over the dictionary matcher's prefetch behavior. [commit](https://github.com/facebook/zstd/commit/93b89fb24b1e019ffc2df027993d04e4c0cadfef)
- Add the public API `ZSTD_sequenceBound()`, which calculates the upper bound on the number of sequences that sequence compression may generate based on input size. [commit](https://github.com/facebook/zstd/commit/aa829988215273f8c8b1423e1a924b326168e09f)
- Complete parentheses for Huffman compression macro expressions to ensure bitwise operations and addition/subtraction are evaluated with the expected precedence. [commit](https://github.com/facebook/zstd/commit/ee6475cbbd04408e721c4daa87d993faf3b3c1cf)
- The compressor and decompressor now support compressed blocks that exactly reach `ZSTD_BLOCKSIZE_MAX`, and explicitly clarify the block size constraints when compatible with older decoders. [commit](https://github.com/facebook/zstd/commit/ea2895cef46d5850b00a9fde57e4e250df680bd3)
- The Huffman code table search stops early when estimating length fallback and allows result differences within a one-byte range to reduce search effort. [commit](https://github.com/facebook/zstd/commit/df714ddb0f2dc076dc841d10c8b72f66ef5af937)
- Add streaming tests for the maximum block size parameter of the compression context, verifying that the set value limits the actual generated compressed block size. [commit](https://github.com/facebook/zstd/commit/53eb5a758c4e618c106eebafa49abde5845f96ef)
- Add explanations for the new regression test for issue #3416, describing the Huffman literal encoding scenarios it covers. [commit](https://github.com/facebook/zstd/commit/ac45e078a5bc22e06d1be1375c25795b7ef3c1ff)
- Add the `ZSTD_c_fastExternalSequenceParsing` parameter to control the fast parsing strategy for external sequences, and resolve automatic mode based on compression level. [commit](https://github.com/facebook/zstd/commit/7f8189ca57741f89b98b06fabfeffb2c8b8683b5)

### Platform Adaptation Layer

- Enable the STATIC_BMI2 compilation path for GCC/Clang and adjust bitstream bit-reading code so that x86 builds supporting BMI2 can use static built-in instructions. [commit](https://github.com/facebook/zstd/commit/7c3d1cb3ab9b43745c65bb1796960dbbaa237a02)
- The largeNbDicts benchmark tool now uses the advanced compression API to set CCtx parameters and reference CDict, making dictionary attachment strategies such as forceCopy and forceAttach effective. [commit](https://github.com/facebook/zstd/commit/f7ebbcd0cc090d8012c906a009521558f70245a7)
- Add the `--prefetch-cdict-tables` option to the largeNbDicts benchmark tool and pass its value to the compression context parameters. [commit](https://github.com/facebook/zstd/commit/6bd5ac671352801cd249576d94606bdc0ef235ec)

### High-Level API & Mode Layer

- Supplement the public header file with descriptions of `ZSTD_initDStream()` and `ZSTD_decompressStream()`'s purpose, calling timing, and streaming input/output state. [commit](https://github.com/facebook/zstd/commit/1c847e2e32f3c2203a9b81b6081b53f9275ec438)
- Add the `ZSTD_decompressionMargin()` API to support in-place decompression of compressed frames, and add related fuzz tests for single-shot and streaming decompression. [commit](https://github.com/facebook/zstd/commit/5b266196a41e6a15e21bd4f0eeab43b938db1d90)

### Application & Tool Layer

- Enhance gzip compatibility mode to support --no-name and --best options, and recognize gzip command aliases to apply corresponding option semantics. [commit](https://github.com/facebook/zstd/commit/e653e97f77e7e53867e39ed6ce11dbbde6617337)
- When multi-threaded decompression is requested, the CLI now prompts that decompression does not support multi-threading, and adds corresponding command-line tests. [commit](https://github.com/facebook/zstd/commit/d4a5bc4efc40e090bf55a1a9221b6ab26b17b302)
- When decompressing to standard output, the CLI adds the `--[no-]pass-through` switch to control passthrough of unknown format input, and enables this behavior by default for cat modes like `zstdcat`. [commit](https://github.com/facebook/zstd/commit/03cc84fddb9747ddc63f76b6f3171cd8f66da202)
- Add compiler optimization parameters to the PGO build target and pass the new options to the stages that generate performance data and recompile. [commit](https://github.com/facebook/zstd/commit/87e169d05d75db5112df20361de33f7398ef27d5)

### Cross-cutting / Other Architecture-related Changes

- Fill in the functional differences between the Python single-file generator and the original shell script, continuing to improve source file filtering and file merging behavior. [commit](https://github.com/facebook/zstd/commit/8f1e51f99fa6ca6d132e53e58265b4d79d2fbb2b)
- Add a GitHub Actions job to build and run Zstandard in an Intel CET-enabled environment, continuously checking CET compatibility. [commit](https://github.com/facebook/zstd/commit/7cf80cb94c23867f7496f6a847f7d4e712dafb86)
- GitHub Actions adds a combined Clang AddressSanitizer and UBSan test task, running the Zstandard test suite to check memory and undefined behavior. [commit](https://github.com/facebook/zstd/commit/66ed3df0967c3cb6446ca5d1b8920f5f4d0170e6)
- Add a GitHub Scorecards workflow to periodically check the project's supply chain security status and on changes to the default development branch. [commit](https://github.com/facebook/zstd/commit/79729f8a2dc15d45a805e1c2f408f739958518b6)
- Add a PGO build task to the short test CI to verify the profile-guided optimization compilation process. [commit](https://github.com/facebook/zstd/commit/aab3dd4312d98b2eff868012a50b1523f41a1a9a)
- Add validation of match length and output literal space for the v0.1 old format decoder to prevent match copying from overwriting input literals. [commit](https://github.com/facebook/zstd/commit/c5bf6b8b88456804b480176c6183a893ca01bf15)
