# Release Note

## Important Changes

### Monitor (MON)

- Dashboard common forms add the cdValidate validation directive to uniformly display required and password rule errors, and mark invalid fields in user password forms. [commit](https://github.com/ceph/ceph/commit/19b7bbeca04518a62e60e7c252b0d0de95c1c645)
- Add differential encoding and transmission to NVMe-oF gateway beacons; Monitor maintains gateway state differences, and MonClient updates mappings accordingly, reducing repeated full state reporting. [commit](https://github.com/ceph/ceph/commit/3b5d28bfa51e3bf024ee0d66acd5cf6eec78eb52)
- Add the NVMEOF_BEACON_DIFF feature bit and compatibility set declaration to Monitor, and update monmaptool's feature bit tests. [commit](https://github.com/ceph/ceph/commit/5467ad93a5bfbe6dfb73e585111a21003acabe91)
- Monitor adds the `nvme-gw listeners` command to return current listener information of NVMe-oF gateways, facilitating query of gateway listening status. [commit](https://github.com/ceph/ceph/commit/e4f6e6a7e0eeedd60a02e80ab97f7d0524c79e90)
- Monitor refuses to enable fast EC optimization for erasure-coded configurations whose chunk size is not aligned to 4 KiB, avoiding optimization with parameters that do not meet alignment requirements. [commit](https://github.com/ceph/ceph/commit/1195a583d829c6b706df111159cc5c02172a2f88)

### RADOS Gateway (RGW)

- Remove the unused cli_version field from the NVMe-oF gateway info return model to avoid exposing useless version information in the API and frontend. [commit](https://github.com/ceph/ceph/commit/f6eec90816e4de67811d4525e30dbf48225b4080)
- Fix Monitor's incorrect modification of the current map when processing late beacons from deleted NVMe-oF gateways, preventing corruption of gateway state mappings. [commit](https://github.com/ceph/ceph/commit/5059a1b8457da0f53e6a60f5a1e9b7d9ef1def56)
- librbd adds the RBD_LOCK_MODE_EXCLUSIVE_TRANSIENT mode and corresponding policy: do not automatically request the exclusive lock, allow peers to wait for the current short-term lock holder to complete operations before taking over. [commit](https://github.com/ceph/ceph/commit/b8e1b4414ece83e331d6ba395b8e214f5728e5c2)

### Object Storage Daemon (OSD)

- BlueStore admin socket no longer outputs space histogram fields inconsistent with the current allocator interface, avoiding providing invalid statistics. [commit](https://github.com/ceph/ceph/commit/6b897f248c4e3f29b55c666ae7031a457ef57ec8)
- BlueStore adds the bluestore_allocator_lookup_policy configuration to choose whether to continue searching for free extents from the last position, improving sequential writes and device write coalescing. [commit](https://github.com/ceph/ceph/commit/6c5bd3dba55c7e53925529707f5d27b524995bf8)
- Fix OSD merge operation's handling of stat invalidation when last_backfill reaches the maximum value, avoiding continued use of incorrect PG statistics after recovery. [commit](https://github.com/ceph/ceph/commit/30c5de8ae202b227c474d2684d09a0d9db43aa7f)
- Add performance counters to the stat invalidation path of OSD peering to record the number of times stats need to be invalidated, facilitating observation of merge recovery behavior. [commit](https://github.com/ceph/ceph/commit/d67279ab83ac0d4360383afd1e46dab7746768ac)
- Fix the issue where BlueFS's volume selector is not updated after envelope WAL recovery completes; refresh the selected volume state after WAL recovery. [commit](https://github.com/ceph/ceph/commit/20b6ce66d30ebabaedf4b31334a8b17bdc179dc6)

### Cross-cutting / Other Architecture-related Changes

- CephFS subvolume info output adds source information when the subvolume is cloned from a snapshot, including source volume, subvolume group, subvolume, and snapshot name. [commit](https://github.com/ceph/ceph/commit/fbba4629cf6182fec31b8d3c391ed86b5b9f9d8f)
- The cephadm module fixes the selection of the internal CryptoCaller so that its own SSH functionality always has access to the real cryptography library. [commit](https://github.com/ceph/ceph/commit/e1949ed6b6321a82d63212950b659c05fcd397a1)
- PG autoscaler introduces dynamic scaling thresholds: scale-down still uses the configured factor, while scale-up lowers the threshold based on the recommended PG count to improve sensitivity to large scale-ups. [commit](https://github.com/ceph/ceph/commit/b907e0b2ebf001b67f0e7d1851d1415576d46a07)
- Add the Nx cache directory of the Dashboard frontend to .gitignore to avoid committing local build caches into the repository. [commit](https://github.com/ceph/ceph/commit/b6020a78d950beb12e216ed2f1d5f9085158ab95)
- Update the CMake project version to 20.1.1, marking the Ceph version corresponding to this maintenance branch build. [commit](https://github.com/ceph/ceph/commit/d9607850c176fd9a1c8f777e2fca91745d47313b)
- Advance the CMake project version to 20.2.0 and fix the working directory path variable in the Debian package build script to ensure release builds write to the correct directory. [commit](https://github.com/ceph/ceph/commit/c7d7bf8b6f6b5acf69d27c9df9407c95ed31863d)
