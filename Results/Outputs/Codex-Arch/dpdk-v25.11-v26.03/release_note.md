# Release Note

## Important Changes

### Driver Layer (PMDs)

- axgbe PMD adds device identification and initialization support for AMD Krackan2e V4000 platform. [commit](https://github.com/DPDK/dpdk/commit/92ad538c329e8da03dea6191b46eab5b425b65d0)
- Intel common Tx code adds transmit path selection infrastructure, selecting matching burst functions for each PMD based on queue and offload configuration. [commit](https://github.com/DPDK/dpdk/commit/910dce5ab07dbdc1cf528562fb9b869fc7fb8542)
- IAVF adds recognition of RSS types for fragmented packets, enabling symmetric Toeplitz hash to cover corresponding IPv4/IPv6 fragment traffic. [commit](https://github.com/DPDK/dpdk/commit/06680fad4a788e55a1d1cd8c12c6b00453b2f423)
- IAVF PMD adds callback interfaces before and after device reset, allowing applications to save state before PF-triggered reset and restore handling after reset. [commit](https://github.com/DPDK/dpdk/commit/a42b8d60b6d90289a42da6da97b3f6223a889690)
- mlx5 adds public RSS TIR registration and deregistration interfaces, allowing applications to register custom RSS steering objects for HWS flows. [commit](https://github.com/DPDK/dpdk/commit/9ec0c6bda04a776f5bb0bea7791d68310cdb8590)
- ZXDH PMD supports runtime modification of transmit/receive queue depth, and validates queue index and device queue context during updates. [commit](https://github.com/DPDK/dpdk/commit/05da61f9b3984f8e16d3735e71e8b78385d3ea9c)
- ZXDH PMD adds link rate setting and auto-negotiation status query, and declares rate configuration support in capability list. [commit](https://github.com/DPDK/dpdk/commit/3db787f6f5d60391a69e9432887b6526b17b6872)
- ZXDH PMD adds secondary process operation support, providing corresponding ethdev operations for secondary processes and maintaining process-specific data. [commit](https://github.com/DPDK/dpdk/commit/360b1d0a89cdc1d2af8363bb15e96bfc13eee1a1)
- ZXDH NP initialization validates PCIe BAR channel number range, rejecting channel numbers outside device mapping range. [commit](https://github.com/DPDK/dpdk/commit/c76668b42b3bf421e829709886d956a1209730ef)
- mlx5 allows running shared Rx queues to be inconsistent with new port MTU, and documents the configuration conditions for shared queues in the guide. [commit](https://github.com/DPDK/dpdk/commit/aab5fcbd6a79954e311c91ba65f7198e7a73ca24)
- Intel common scalar Tx adds function to calculate context descriptor count based on transmit offload requirements, for reuse by drivers like i40e. [commit](https://github.com/DPDK/dpdk/commit/2904020f8313b0bd6adcdd1cd522b05ec30691d0)
- Intel common Tx functions add IPsec descriptor callback interface, enabling different PMDs to integrate security offload metadata into the common transmit path. [commit](https://github.com/DPDK/dpdk/commit/fd1e6458b3d21ff5b71d2826ff7428a55866518a)
- Intel Tx descriptor supports selecting L2TAG1 insertion value based on mbuf VLAN field, and allows each PMD to handle VLAN information in context descriptors separately. [commit](https://github.com/DPDK/dpdk/commit/6ea6d67bebfe86feefa5ffe1fabcf8dfe77f87df)
- Intel common scalar Tx adds fast path branch for packets that occupy only one descriptor and do not have TSO enabled, reducing transmit path checks and writes. [commit](https://github.com/DPDK/dpdk/commit/2d17ea27de46d56edbbc7d47abc024f85d99853c)
- IDPF enables single-queue simple Tx burst function, sending via single-descriptor packet path to reduce transmit processing overhead. [commit](https://github.com/DPDK/dpdk/commit/376faf4aaa1638209b26ac820d8cd68f26dda529)
- CPFL adds simple Tx path availability check, and enables simple transmit burst when device configuration meets conditions. [commit](https://github.com/DPDK/dpdk/commit/e165a4bd0a8ae84c16e17b165ed6a1adaae60dfe)
- ixgbe PMD adds E610 MAC type check, and clears PFVTCTL pooling mode during device initialization as required for E610/X550. [commit](https://github.com/DPDK/dpdk/commit/ffac9bc95aa8311c1e9f2bd590a015532d31c3ad)
- r8169 PMD adds RTL8168KD initialization and MCU configuration support, enabling the driver to recognize and start this NIC model. [commit](https://github.com/DPDK/dpdk/commit/521ecb813a9dd850f73854b12cf231271cf3c011)
- r8169 adds RTL9151 chip identification and initialization implementation, enabling PMD support for this NIC model. [commit](https://github.com/DPDK/dpdk/commit/7acd73204fa99f1bbfe62ef84ca6c459e7f6d365)
- r8169 adds chip detection and hardware initialization support for RTL8125K. [commit](https://github.com/DPDK/dpdk/commit/e0373eac0dcb290b50911609b2fcaf16f5a02405)
- GVE PMD adds device reset handling path, and records reset support in driver guide and 26.03 release notes. [commit](https://github.com/DPDK/dpdk/commit/1bf64edce3c4010b539f27094173128c5a553c2e)
- CN20K validates CPT completion code before processing SA soft expiration, avoiding treating failed hardware requests as successful expiration events. [commit](https://github.com/DPDK/dpdk/commit/a3ccdf183632f4732633524e9570d7b73c8dab20)
- CN20K inline IPsec fast path adds out-of-place support, outputting processing results to a separate mbuf buffer. [commit](https://github.com/DPDK/dpdk/commit/9f13f3d0691a192cca2eaafbf861b1949174d1d1)
- CN20K outbound IPsec Tx path enables PDB parameters, providing CPT descriptors with protocol metadata needed to construct secure packets. [commit](https://github.com/DPDK/dpdk/commit/46448417ac5cf4e82258c69cdbc2806268fca182)
- Intel PMD allows secondary processes to start and configure devices, and fixes state handling during secondary process queue path initialization. [commit](https://github.com/DPDK/dpdk/commit/af7ae88302578da576ad898be044c8f14c433dfa)
- ICE base layer adds PPP and PPPoE header structure definitions for L2TPv2, providing field layouts for protocol parsing and filter matching. [commit](https://github.com/DPDK/dpdk/commit/d1f8553d5d7ea36f9bf81f156de25bf230fea240)
- ICE PMD adds L2TPv2 tunnel type definition for flow rule parsing to identify this tunnel protocol. [commit](https://github.com/DPDK/dpdk/commit/5a6292de5fd8016f7cb12e6905385dea161811f7)
- ICE flow parser adds L2TPv2 header, PPP, and PPPoE protocol field definitions to support describing this tunnel packet structure. [commit](https://github.com/DPDK/dpdk/commit/a4bd231eaaae3caaed1146de923dccc888d115c3)
- ICE FDIR supports creating L2TPv2 flow pattern rules, parsing tunnel headers and offloading matching conditions to hardware filters. [commit](https://github.com/DPDK/dpdk/commit/733640dae75e4edb1aaefc4150cbb9cac4303cdb)
- ICE FDIR adds L2TPv2 packet header generation handling, enabling hardware flow filtering rules to construct and identify corresponding tunnel layers. [commit](https://github.com/DPDK/dpdk/commit/512e4d428ca648f94cbeda78ffea54e4da639340)
- ICE RSS supports hash calculation based on L2TPv2 tunnel packets, and records this capability in the 26.03 release notes. [commit](https://github.com/DPDK/dpdk/commit/02d9f41bada6b5f6af2e58430cde2e11f1c3712a)
- IDPF adds AVX2 Rx burst path for split queue configuration, using vectorized batch processing of receive descriptors and mbufs. [commit](https://github.com/DPDK/dpdk/commit/1f065f9d75ff7319be31618c45670406306268af)
- IDPF adds AVX2 Tx burst path for split queue configuration, and records this transmit capability in the 26.03 release notes. [commit](https://github.com/DPDK/dpdk/commit/57560a92167a96952e32387a76a02e947cdd3cc0)
- IDPF virtchnl2 base interface adds PTP capability and time synchronization message definitions, providing protocol fields for NIC-PF timestamp service negotiation. [commit](https://github.com/DPDK/dpdk/commit/3e175561a4fc21d4b94ed76cbb2e5caf1543658c)
- IDPF PMD negotiates PTP capability with PF and handles time synchronization requests, enabling hardware clock functionality on the device. [commit](https://github.com/DPDK/dpdk/commit/cdf4b9ded461af79e9cd3f8ffeab97548cd0077e)
- IDPF PMD adds timesync API support, and declares timestamp and clock synchronization capabilities in feature list and guide. [commit](https://github.com/DPDK/dpdk/commit/1c6e2737fd3e43b57f0502f11ca70066b6703157)
- ICE base driver adds LLDP filter control capability for E830, allowing firmware to enable or disable LLDP receive filtering as configured. [commit](https://github.com/DPDK/dpdk/commit/9e90c619d41f012b32f604192141b248dbd4933f)
- ICE AdminQ adds interface to query pending events, enabling driver to check and process unread management queue events. [commit](https://github.com/DPDK/dpdk/commit/d804a8cbf7439692bfab2171f32cae33536dcced)
- BNXT Rx path adds recognition of PTP packets, ensuring time synchronization packets enter receive processing and can obtain timestamps. [commit](https://github.com/DPDK/dpdk/commit/29a075c290e1e2be9d8e2e29e0c5b6dfc3ffb528)
- BNXT Tx queue parses PTP packets and sets transmit timestamp requests, enabling hardware to generate timestamps for outbound synchronization packets. [commit](https://github.com/DPDK/dpdk/commit/5722ed1aafd2fc5ad44e432a4f6c7bd337c673d8)
- BNXT Thor2 VF adds PTP capability recognition, fixing time synchronization hardware command configuration on this model's virtual functions. [commit](https://github.com/DPDK/dpdk/commit/a075b33deafb1a1e83d3fb04b0c65775d77d416b)
