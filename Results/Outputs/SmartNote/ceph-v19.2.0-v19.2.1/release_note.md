# v19.2.1
## 🐛 fix
- Fixed a monitor election issue in stretch clusters where a network partition between data centers could stall the election, making the cluster inaccessible. An out-of-quorum data center influenced the tiebreaker monitor, forcing it to increase its epoch and reject the victory message from in-quorum monitors. The CONNECTIVITY election strategy now ignores proposals from monitors marked as down, preventing out-of-quorum monitors from affecting the tiebreaker and allowing in-quorum monitors to complete the election. A test confirms cluster accessibility, active placement groups, and successful read/write operations during a network partition. [#58669](https://github.com/ceph/ceph/pull/58669)
- Fixed CRUSH MSR feature handling by using the correct feature mask, preventing assertion failures. Erasure code profile creation now includes a compatibility check, and validation has been improved for flexibility. The cluster requires the CRUSH_MSR feature if any CRUSH rule is of type msr, even if no pool uses it, preventing rule creation until compatibility is ensured. Compatibility settings are applied for erasure code profiles with a specific parameter. Validation ensures all connected clients support CRUSH_MSR; the monitor returns an error if any client lacks it. [#59492](https://github.com/ceph/ceph/pull/59492)
- Fixed a race condition in the Ceph client by ensuring calls to _ll_fh_exists() are made while holding the client_lock. Lock acquisition moved earlier in several functions to prevent invalid file handle checks, and clamping of length parameter to INT_MAX moved before the lock for consistency. Resolves issue #67565. [#59487](https://github.com/ceph/ceph/pull/59487)
- Fixed a dangling pointer in RGW notifications by using unique_ptr for the completion pointer and replacing DoutPrefixProvider with CephContext. Replaced a vector of raw topic pointers with a map of unique pointers to avoid the deprecated `rd_kafka_topic_name()`. Topic lookup now uses name-based map search instead of linear search, and the comparison operator was removed. Queue length checks are now skipped for expired topics, as other tests already cover this. Unnecessary delays have been removed, and topic stats checking after object creation and deletion has been adjusted. Fixed segmentation fault from null bucket pointer in bucket notification topic listing. Corrected listing logic to use appropriate method based on zone group support and older topics. Admin command and REST API now handle pagination for newer topic format with fallback to older listing. Updated test cases to use a helper function for listing topics. Updated RGW notification test scripts to use host's real IP instead of localhost. RabbitMQ server configuration now allows "guest" user to connect from non-localhost addresses. Service management commands changed to systemctl. Added two new admin commands to bucket notification documentation: `topic stats` for persistent topic statistics and `topic dump` for pending notifications in JSON format. Removed obsolete pubsub subscription commands. Enabling notification_v2 migrates existing metadata and enables data syncing between zones. ## ✨ feat
- TPM2 token enrollment for encrypted OSDs allows automatic unlocking of LUKS2 devices during boot via TPM 2.0. Use `--with-tpm` with `ceph-volume lvm prepare` or `raw prepare`, or set `tpm2: true` in OSD specifications for cephadm. [#59196](https://github.com/ceph/ceph/pull/59196)
- When a device supports end-to-end data protection, CRC calculation for the header is skipped. Read and write functions utilize this protection, disabling CRC when enabled, with a new function to check device capabilities. Extents on such devices use a null CRC value. The superblock is used for the metadata header. Exception handling logs errors and returns an error on ioctl failure. During mkfs, end-to-end data protection is enabled if the device supports it, by checking for checksum offload support and formatting with protection type 2. The superblock stores a feature flag, and during mount, the device's support is verified. [#59298](https://github.com/ceph/ceph/pull/59298)
- Uses cls_version to prevent race conditions between part uploads and multipart complete operations in RGW.
